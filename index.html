How write-back works

  1. Propose – a Cherrywork agent or user drafts the action with justification and the data it used.
  2. Re-validate – a live S/4HANA check confirms the situation still holds (stock still free, order not yet released past the op).
  3. Approve – SAP Build Process Automation routes to the approver role for that action type.
  4. Post – SAP Integration Suite calls the released S/4HANA API; SAP applies its normal checks.
  5. Trace – SAP document number returned; the twin reflects the change on the next CDC cycle.

    A question, end to end

    1. User asks the Operations Agent “Why is order 1000482317 waiting?” (SSO via Cloud Identity).
    2. Operations Agent routes to the Exception Investigator (SAP AI Core, model via generative AI hub).
    3. MCP tools read live status from S/4HANA (Integration Suite) and history from BigQuery data products.
    4. Answer returns with sources and timestamps, plus a recovery option.
    5. User selects the option → proposal in Build Process Automation → approver → S/4HANA API.
